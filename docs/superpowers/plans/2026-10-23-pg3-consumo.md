# PG3: voice and e-mail charging, low balance, and billing e-mail fixes — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task by task.

**Goal:** Voice and e-mail draw on the house's single wallet, the same way SMS does. When a house runs out of balance, only that house is affected. The house is warned before the balance runs out. Billing e-mails get fuller copy, and a manual settlement can carry a payment date.

**Architecture:**
- Reuse the PG1 wallet: `wallet_reserve` and `wallet_refund` stay as they are.
- New SQL function `wallet_settle`, which settles a reservation by the actual units used and returns the unused share as a `usage_refund` row.
- Error type `insufficient_balance`, carried as `errorKind` from the senders up to the dispatchers.

**Stack:**
- TanStack Start (`createServerFn`) and Supabase/Postgres.
- Vitest, with PGlite for the db tests.

**Spec:** `docs/superpowers/specs/2026-10-23-pg3-consumo-design.md`. Its numbered decisions are binding.

## Global Constraints
- New migrations are numbered after `20261023100100`: `20261024100000`, `20261024100100`, `20261024100200`.
- Never edit migrations that have already been applied.
- Grants:
  - new wallet/settle functions go to `service_role` only;
  - admin functions check `is_super_admin()` or `has_tenant_access` in SQL.
- SMS behaviour does not change; the existing SMS tests stay green.
- Exempt houses (`billing_tenant_exempt`) are charged R$ 0, but their usage is still counted.
- The demo house never sends.
- A locked house never reserves, because the guard runs before the reservation.
- User-facing copy is in pt-BR.
- Never put a literal NBSP in source; use ` ` or `String.fromCharCode(160)`.
- Never delete rows that carry money.
- Supplier cost is visible only to the superadmin.
- Before handing in, run `npm test`, `npm run typecheck` and `npm run lint`; all must pass.

## Review Focus
1. **Repeated voice callback:** charges once. Enforced by the unique index `idx_wallet_ledger_reverses_once`.
2. **No balance in one house:** never pauses a channel for other houses. This is the production bug in `sms-dispatcher.server.ts:716-742` and in `email-automations.server.ts:835-848`.
3. **Franchise boundary:** 99,999 / 100,000 / 100,001 e-mails in a month, plus a 2-unit reservation that straddles the boundary.
4. **Status 0 with `errorKind="insufficient_balance"`:** in the call queue it must not be treated as transient, otherwise the call is re-queued forever.
5. **Provider refusal:** always refunds, and gives the franchise unit back.

### Task 3: SQL — settlement by actual usage, plus voice and e-mail billing columns
**Migration:** `supabase/migrations/20261024100000_billing_wallet_settle.sql`.
- `alter table billing_price_book add column charge_unanswered_blocks int not null default 0 check (charge_unanswered_blocks >= 0)`.
  - Update the superadmin price-setting function so it accepts the value: new overload with `drop` and `create`, and redo the grants.
  - Show the value in the existing superadmin price form, for item `voice_30s` only.
- `wallet_settle(_tenant uuid, _reference_id text, _actual_units int, _idempotency_key text, _reason text) returns jsonb`:
  - Lock the wallet and find the reservation (`usage_reservation` with that reference).
  - Clamp `_actual_units` to `[0, reserved]`; record `over_cap` in metadata when it was over.
  - Write a `usage_refund` row with:
    - `reverses_ledger_id` = the reservation;
    - `units` = units returned;
    - `amount` = the proportional share of the reserved amount (0 for exempt houses; never reprice);
    - `metadata {settlement:true, actual_units, over_cap?}`.
  - Write that row even when nothing is returned, so the reservation is marked settled.
  - Decrement `tenant_monthly_usage` (units and amount) by the delta.
  - For the e-mail item, give returned units back to the franchise (`free_units_used`), following the logic of `wallet_refund`.
  - Idempotency: the same key returns the previous result. A different key on a reservation already reversed returns `already_reversed`.
- `wallet_settle_voice(_tenant, _reference_id, _duration_seconds int, _answered bool, _idempotency_key) returns jsonb`:
  - blocks = `answered and duration>0 ? ceil(duration/30.0) : charge_unanswered_blocks`, taken from the price row that was in force at reservation time;
  - then calls `wallet_settle`.
- `call_history`: add `billing_reference_id text`, `billed_blocks int`, `billed_amount numeric(14,4)` and `billing_settled_at timestamptz`.
- `email_send_logs`: add `billing_reference_id text` and `billed_amount numeric(14,4)`.
- Grants: `wallet_settle*` to `service_role` only.
- Regenerate `src/integrations/supabase/types.ts` for the new columns (by hand, following the existing pattern).

**Tests:** PGlite, in `src/lib/billing/billing-wallet.db.test.ts` or a new `billing-wallet-settle.db.test.ts`.
- Durations: 61 s = 3 blocks = R$ 0,27; 45 s = 2; 30 s = 1.
- Unanswered: 0 by default, and R$ 0,09 when the rule is set to 1.
- A repeated settle is idempotent.
- A refund after a settle is refused, and a settle after a refund is refused.
- Exempt house: charged 0, usage counted.
- Reservation in one month and settlement in the next: decrement the reservation's month.

**Commit:** `feat(billing): wallet_settle and voice/e-mail billing columns`
